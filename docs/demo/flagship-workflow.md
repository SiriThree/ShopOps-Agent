# ShopOps 旗舰演示工作流

## 1. 演示目标

展示 ShopOps 是多店铺运营平台，并说明 Agent 如何在权限、模板、审批、幂等和审计约束下完成自动化任务。

## 2. 准备

1. 准备 JDK 17、Maven 3.9+、Node 20+、MySQL 8.4。
2. 使用 dev profile，仅在本地演示时启用 Header 开发认证。
3. 执行 `python scripts/prepare_olist_demo.py` 准备公开 Olist 数据。
4. 启动后端和前端，或使用 `deploy/docker-compose.demo.yml`。
5. 先访问 `/actuator/health/readiness` 检查就绪状态。

## 3. 推荐正常路径：差评分析与经营报告

```text
运营总览
→ 选择当前店铺
→ 查看待处理差评/异常提示
→ 进入自动化工作台
→ 创建 comment_risk 或 daily_review 任务
→ 查看受控计划和工具调用
→ 查看报告
→ 跳转任务、工具日志、审计和 Trace
```

这条路径基于公开文件数据、规则 Planner、Tool Gateway、报告和审计，属于当前最接近可重复运行的演示链路。

## 4. 高风险审批路径：退款执行

```text
创建 order.refund_execute 请求
→ Tool Gateway 检查权限与 HIGH 风险
→ 创建审批请求和参数摘要
→ 审批中心查看 tenant/shop、业务对象、工具和摘要
→ 同意或拒绝
→ 同意后再次校验执行参数
→ 幂等记录
→ 模拟外部退款调用
→ 状态回查/本地确认
→ Outbox、审计和 Trace
```

重要边界：当前退款客户端是模拟适配器，不能演示为真实平台退款。

## 5. 异常路径

| 场景 | 当前演示方式 | 边界 |
|---|---|---|
| 审批拒绝 | 在审批中心拒绝请求 | 应保持不可执行 |
| 重复审批 | 重复提交相同决策 | 条件更新应避免重复触发 |
| 参数篡改 | 审批后改变实质参数 | 摘要不一致应拒绝 |
| 重复写请求 | 使用相同 operationRequestId | 应返回既有结果或拒绝并发执行 |
| 外部超时 | 模拟适配器返回未知 | 进入 EXTERNAL_UNKNOWN，先回查 |
| 权限不足 | 使用缺少 tool/agent 权限的用户 | 后端返回统一 403 |
| 跨店铺 | 修改 shopId 为未分配店铺 | 后端成员关系校验拒绝 |
| 任务取消 | 对非终态任务请求取消 | 进入 CANCEL_REQUESTED/CANCELLED 语义 |
| 重复消息 | 重复投递同一 taskId | 数据库租约阻止并发执行 |
| Worker 崩溃 | 当前只能检查租约过期字段和恢复入口 | 周期心跳与完整自动接管未完整验证 |
| 审批过期 | 需要测试数据或时间控制 | 当前不应宣称已完成完整 UI 演示 |

## 6. 演示结束时必须说明

- 数据来自公开数据或人工构造，不是真实商家生产数据；
- 高风险退款是模拟外部适配器；
- 当前环境若未运行 Maven、Docker、E2E 和 k6，不能展示为已通过；
- Agent 是平台内部工作流模块，不拥有业务权限。
