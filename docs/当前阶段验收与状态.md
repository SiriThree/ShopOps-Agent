## 1. 当前阶段定位

ShopOps Agent 当前已经从设计文档和后端骨架推进到“可运行、可观测、可审计、可审批”的 P0-P5 API 集成版本。

当前后台闭环：

```text
创建每日经营复盘任务
  -> Agent 任务执行
  -> Planner 生成工具计划（可配置走 Model Gateway，默认规则兜底）
  -> Tool Gateway 调用 P0 工具
  -> 生成运营报告
  -> 记录步骤、事件、工具日志、Trace
  -> Dashboard / 任务队列 / 报告 / 工具日志 / 认证 / 审计中心展示
```

### P5 审批中心 API v1

状态：已完成审批单模型、memory/JDBC 双实现、Flyway 迁移、API、角色验收测试、高风险工具调用前置审批拦截、审批通过后的带审批单重试执行、批量通过/驳回、审批超时关闭、高风险审批二次确认，以及审批事件接入 Audit Center 时间线。

已具备：
- 审批单表：`approval_request`
- Flyway 迁移：`V8__p5_approval_request.sql`
- 审批单创建：`POST /api/admin/approvals`
- 审批单列表：`GET /api/admin/approvals`
- 审批单详情：`GET /api/admin/approvals/{approvalId}`
- 审批通过：`POST /api/admin/approvals/{approvalId}/approve`
- 审批拒绝：`POST /api/admin/approvals/{approvalId}/reject`
- 批量通过：`POST /api/admin/approvals/batch/approve`
- 批量驳回：`POST /api/admin/approvals/batch/reject`
- 关闭超时审批：`POST /api/admin/approvals/expire-stale`
- 角色边界：
  - `OPERATOR` 及以上可创建审批单。
  - `ADMIN` 可审批通过或拒绝。
  - `VIEWER` 只能读取，不能创建或审批。
- 状态流转保护：已处理审批单不能再次通过或拒绝。
- 工具网关联动：`needApproval=true` 的工具会返回 `APPROVAL_REQUIRED`，并自动创建待审批单。
- 审批后重试：审批通过后，请求同一工具并携带 `approvalId` 可继续执行。
- 二次确认：`HIGH` 风险审批通过前必须输入确认语 `确认通过`，单条审批和批量通过都按同一规则校验。
- 审批审计：Audit Center 支持 `APPROVAL_CREATED` / `APPROVAL_DECIDED` / `APPROVAL_EXPIRED` 时间线事件。
- 审批超时：可按 `timeoutMinutes` 与 `limit` 批量关闭超时待审批单，并记录为 `EXPIRED` / `CANCELED` 审计事件。
- 高风险演示工具：`order.refund_execute`

## 4. 条件验收项

以下验收依赖本地 Docker 基础设施，默认测试不会自动执行。

### JDBC 集成测试

前置：

```powershell
docker compose -f deploy/docker-compose.dev.yml up -d
```

命令：

```powershell
mvn -pl shopops-admin test "-Dshopops.jdbc.it=true" "-Dtest=AgentTaskJdbcFlowIntegrationTest,AgentTaskJdbcFailureIntegrationTest,AuthAuditJdbcIntegrationTest,AuthTokenLifecycleJdbcIntegrationTest"
```

验证目标：
- Flyway 迁移。
- MyBatis/JDBC 持久化。
- 任务主链路与失败链路。
- 认证审计与 Token 生命周期。


## 6. 下一步建议

建议下一阶段继续补齐广告、报表等外部数据源，或建设连接器外部 API 调用审计。

原因：
- 它承接 P3 的角色权限。
- 它补齐工具风险等级的业务闭环。
- 它能直接进入 P4 审计中心，形成企业治理亮点。
- 它比立刻重写 React 前端更能提升项目核心能力。

推荐拆分：

```text
1. 增强审批多级审批、金额阈值等策略。
2. 建设广告、报表等真实电商连接器。
3. Prompt 模板补差异对比、复制版本、删除草稿等高级编辑能力。
```

## 7. 当前可对外讲法

当前项目不是一个简单的“调用大模型生成报告”的 demo，而是一个已经具备企业 AgentOps 雏形的后端平台：

- 有任务生命周期管理。
- 有工具注册和受控调用边界。
- 有报告中心和证据链。
- 有 Trace 与审计时间线。
- 有认证、Token、角色权限和审计。
- 有 MySQL / Redis / RabbitMQ / Flyway / MyBatis 的工程化基础。
- 有可演示的中文管理台。

下一步补齐多级审批策略和演示数据脚本后，项目会更接近完整的企业级 Agent 治理平台。
