# ShopOps Agent 当前阶段验收与状态

更新时间：2026-07-21

当前结论：项目已经完成 P0 主链路、P2 管理端 API、P3 认证与审计、P4 审计中心、P5 审批中心、Model Gateway、Prompt 模板管理、连接器治理中心，以及经营复盘所需的五类外部文件数据源。当前形态适合做后端能力验收、面试展示和下一阶段功能迭代；还不是最终的 React / Ant Design Pro 产品化前端。

## 1. 已完成内容

### P0 每日经营复盘主链路

状态：已完成。

已具备：

- `daily_review` 任务创建与执行。
- Planner 生成固定工具链，支持通过 Model Gateway 生成计划，并对模型计划做安全校验和规则兜底。
- 工具链已包括：
  - `order.query_summary`
  - `comment.query_negative`
  - `product.query_candidates`
  - `ad.query_performance`
  - `report.query_external_metrics`
  - `report.generate_daily_review`
- 报告生成已纳入订单、评论、商品、广告和平台报表指标。
- 任务步骤、任务事件、工具调用日志、Trace Span 和运营报告均已沉淀。
- memory 模式默认可运行；JDBC 模式已有 Flyway 表结构和条件集成测试。

### 认证、权限、审批和审计

状态：已完成核心治理闭环。

已具备：

- 登录、退出、当前用户、Bearer Token 与 Header 开发模式。
- `VIEWER`、`OPERATOR`、`ADMIN` 角色权限。
- 高风险工具前置审批拦截。
- 审批单创建、列表、详情、通过、拒绝、批量处理、超时关闭。
- 高风险审批二次确认语：`确认通过`。
- Audit Center 聚合 `AUTH`、`TASK`、`TOOL`、`APPROVAL`、`CONNECTOR` 来源事件。
- 审计时间线、详情、风险聚合、CSV 导出。

### Model Gateway 与 Prompt 模板

状态：已完成第一版骨架。

已具备：

- 统一模型调用入口。
- provider 抽象、echo provider、OpenAI-compatible provider。
- 调用日志 memory/JDBC 双存储。
- 超时、重试、失败降级。
- Planner 和 Report 生成均可配置接入 Model Gateway，并保留规则兜底。
- Prompt 模板版本管理、启用版本、预览和渲染测试。
- 真实模型演示脚本：
  - `scripts/start-model-gateway-demo.ps1`
  - `scripts/verify-model-gateway-demo.ps1`
  - `docs/真实模型网关演示.md`

### 外部业务数据源与连接器治理

状态：已完成经营复盘核心输入的文件连接器版本。

已具备：

- 五类文件连接器：
  - `file.order-summary`
  - `file.negative-comments`
  - `file.product-candidates`
  - `file.ad-performance`
  - `file.external-reports`
- 对应配置项：
  - `shopops.connector.order-summary.file`
  - `shopops.connector.negative-comments.file`
  - `shopops.connector.product-candidates.file`
  - `shopops.connector.ad-performance.file`
  - `shopops.connector.external-reports.file`
- 未配置或未命中时自动回退默认演示数据。
- 连接器状态中心：`GET /api/admin/connectors/status`
- 连接器凭证管理 memory/JDBC 双实现，支持掩码展示、停用、连通性测试、过期时间和轮换提醒。
- JDBC 模式凭证明文使用 `shopops.connector.credential-secret` 派生密钥后以 AES-GCM 密文入库。
- 同步任务、失败重试、最大重试次数保护。
- 外部 API 调用审计与 `CONNECTOR` 审计事件。

## 3. 条件验收项

以下验收依赖本地 Docker 基础设施，默认测试不会自动执行：

```powershell
docker compose -f deploy/docker-compose.dev.yml up -d
```

JDBC 集成测试：

```powershell
mvn -pl shopops-admin test "-Dshopops.jdbc.it=true" "-Dtest=AgentTaskJdbcFlowIntegrationTest,AgentTaskJdbcFailureIntegrationTest,AuthAuditJdbcIntegrationTest,AuthTokenLifecycleJdbcIntegrationTest"
```

RabbitMQ 异步任务分发：

```powershell
mvn -pl shopops-admin test "-Dshopops.rabbitmq.it=true" "-Dtest=AgentTaskRabbitDispatchIntegrationTest"
```

## 5. 下一步建议

建议下一阶段优先做“用户与租户管理页面”或“多级审批策略”。

推荐顺序：

```text
1. 用户 / 租户 / 店铺成员管理 API 与页面
2. 多级审批、金额阈值、工具风险等级审批策略
3. Prompt 模板差异对比、复制版本、删除草稿
4. React / Ant Design Pro 产品化前端重构
```

原因：这些能力最能承接当前已经完成的认证、角色、审计、审批和工具风险体系，比立刻重写前端更能提升项目的企业级治理完整度。
